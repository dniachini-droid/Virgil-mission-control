# V1 boundary

Deliverable 3. V1 is the product at the end of Phase 3: one owner supervising governed agent work on allowlisted repositories through the two worlds, with the owner-only merge gate. Phases 4 to 6 extend it.

## Inside V1

- Orbital Foundry for allowlisted repositories: real branch, SHA, PR, check and review state (Phase 2); governed single-hop session launching in isolated worktrees with structured result ingestion (Phase 3).
- The full chain: scope, owner acceptance, plan, build, deterministic verification, independent review, bounded repair, fresh re-review, owner merge decision.
- Evidence View, timeline replay of a run, and the Mind of Virgil with the Archive Nebula, Synaptic Forge and Living Knowledge Galaxy for the project's knowledge.
- Deterministic gates enforced at runtime; per-role write enforcement through hooks.
- Desktop and mobile, reduced motion, quality tiers.

## User journeys

1. Commission an idea; accept the Cartographer's bounded scope; watch the Architect's plan; authorise the build.
2. Follow a sealed candidate through verification and independent review; inspect any object's exact evidence.
3. See a candidate quarantined with a stable finding; authorise (or refuse) a second repair round.
4. Open the airlock for an eligible candidate; watch deployment start, fail or succeed as distinct states.
5. Enter the Mind: trace a lesson to the run and source that support it; see a contested claim; run a Mind Scan.
6. Replay a run to any event and see what was believed, which artifact existed and which authority was active.

## Acceptance criteria (V1)

Derived from commission sections 5.5, 5.6, 6.1, 7 and 13 and Amendment 1: every gate in `packages/gate-engine` computed from live evidence; every state in the state language reachable and distinct; every authenticated animation traceable to an event; no other repository reachable; no merge or deploy without an owner decision event; the wiki free of copied live state under Mind Scan.

## Outside V1 (non-goals)

Multi-project portfolio navigation, cost telemetry, alerts, project creation from templates, production knowledge compilation, recurring observation, sound design beyond optional motifs, native mobile apps, any model's private reasoning display, any autonomous merge or deploy.

## Assumptions

Claude Code sessions are the agent runtime; GitHub is the remote; Git worktrees isolate builds; the owner uses a desktop with a GPU for primary supervision and a phone for monitoring.

## Open owner decisions before Phase 1

Recorded in `docs/process/PHASE_0_RUN_RECORD.md`: the art-direction checkpoint verdict; character direction (stylised humanoid, semi-organic machine, drone or hybrid ensemble); whether optional sound is in the Phase 1 slice.
