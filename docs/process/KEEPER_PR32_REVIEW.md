**Surface:** `packages/gate-engine/src/handoff.ts:210-218`.

`ordered` is decided by `pushedBy.get(h.sha)`, an exact string lookup. `scripts/virgil-chain.ts:248-249` always writes `sha=${short}`, `head.slice(0, 7)`. `scripts/virgil-chain.ts:57-93` (`--emit`, the reviewer's only route) passes `--sha` through **verbatim, unnormalised**, and `.claude/agents/keeper.md:110` gives the reviewer `--sha <reviewed-sha>`, the review brief `--sha <the head SHA>`. Seven characters on one side, forty on the other. The lookup misses, `pushed` is `undefined`, and the guard concludes the chain is in order.

**Reproduction, using only the repository's own commands:**

```

virgil:handoff role=reviewer round=0 sha=8ba445262c15c487f0...   (marker, comment syntax stripped so this illustration is not itself counted)

next=review
because 8ba4452 was pushed and no reviewer has reported on it
```

Position is derived from `h.role !== 'reviewer'` on a marker that parsed. Both halves of that are the session's own output, so KXR-44/PR26's mechanism — *the count reads a word the session chooses* — is narrowed to one spelling, not closed. Two ways through, both unbounded:

**(a) A pushing session that spells itself `reviewer`.** `scripts/virgil-chain.ts:57-87` accepts `--emit reviewer` from any session; the only condition is a `--verdict`, and `--facts` refuses a reviewer, so no facts block is owed either. With `build, review(BLOCKED)` followed by any number of repair comments emitted as `reviewer BLOCKED`:

```

roundsUsed=0/1 ordered=true => nextStep=fix round=1   (10 rounds deep)
```

**(b) Nobody lies at all — the repair's marker just doesn't parse.** `readChain` ignores anything unparseable by design. A fix session that pushes and posts prose, or whose marker lacks `sha`, is invisible:

```
1 silent fix round already run -> nextStep=fix round=1
6 silent fix rounds already run -> nextStep=fix round=1
```

Six repair sessions in, the chain still says *round 1 of 1 is authorised*. The docstring at `handoff.ts:134-141` anticipates exactly this — under-counting is "the *unsafe* direction" — and says it is "compensated by `nextStep` refusing whenever the count is not strictly below the authorisation". **That compensation never engages, because the count is pinned at zero.**
